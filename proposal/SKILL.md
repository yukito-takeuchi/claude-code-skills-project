# 提案資料作成スキル

CLAUDE.mdのコンテキスト（AIworkerの事業・自分のポジション）を踏まえ、tl;dvの文字起こしから提案資料テキスト＋スライド構成アウトラインを生成する。

## 自動化する範囲

```
tl;dv文字起こし貼り付け
  ↓ 【自動】提案資料テキスト生成（Google Docにコピペ用）
  ↓ 【自動】スライド構成アウトライン生成（Canva作業の叩き台）
  ↓ 【手動】Canvaで自社フォーマットに落とし込み・最終調整
```

※ pptx自動生成はしない（Canvaフォーマットが崩れるため、アウトライン止まりが現実的）

## 入力の受け方

- **`/proposal`（引数なし）**：以下のメッセージを表示して入力を促す
- **`/proposal 研修`** など案件種別あり：種別を確定した上で文字起こしを促す
- **文字起こしが貼られたら**：即座に解析・生成を開始する

引数なし・文字起こしなしの場合のメッセージ：
```
tl;dvの文字起こしを貼り付けてください。
案件種別（研修 / コンサル / 開発）がわかれば一緒に教えてもらえると精度が上がります。
不明な場合は文字起こしから推測します。
```

## AIworkerの案件種別

案件種別が不明な場合は、文字起こしの内容から以下の基準で推測する：

| 種別 | 内容 | 判断基準 |
|------|------|----------|
| **研修** | 社内向けAIリテラシー・活用研修 | 「社員に使わせたい」「研修」「教育」「学ばせたい」 |
| **コンサル** | AI導入戦略・業務改善提案 | 「何から始めれば」「どう活用すれば」「戦略を立てたい」 |
| **開発** | AIを活用したシステム・ツール開発 | 「作りたい」「自動化したい」「ツール」「システム」 |

## 出力フォーマット

### 冒頭ヘッダー

```
【提案資料骨子】
顧客名/会社名：（文字起こしから読み取れる場合のみ）
案件種別：研修 / コンサル / 開発（推測の場合は「推測：〇〇」と明記）
```

---

### 出力①：提案資料テキスト（Google Doc用）

#### 1. 顧客の課題
- 文字起こしから顧客の言葉ベースで課題を抽出する
- 表面的な課題と本質的な課題を分けて整理する
- 箇条書き3〜5点

#### 2. 提案内容・解決策
- AIworkerの該当サービスで提供できる解決策を具体的に書く
- 「なぜAIworkerが対応できるのか」の根拠を含める
- 顧客の言葉・業界に合わせた表現を使う

#### 3. 期待される効果
- 導入後に顧客が得られる変化・メリット
- 定量的な効果（時間削減・コスト削減など）があれば記載
- 定性的な効果（業務フロー改善・組織変化など）も含める

#### 4. 次のアクション・見積もり感
- 商談後の具体的なネクストステップ
- AIworker側と顧客側それぞれのアクションを書く
- 費用感・スケジュール感（文字起こしから読み取れる範囲で記載）

---

### 出力②：スライド構成アウトライン（Canva作業の叩き台）

各スライドに「タイトル＋記載すべき内容の箇条書き」を出力する。

```
スライド1：表紙
- 会社名・提案タイトル
- 提案日

スライド2：現状の課題
- 顧客が抱えている課題（①で整理した内容をスライド向けに要約）

スライド3：提案内容
- AIworkerが提供するソリューション
- 対応サービスの概要

スライド4：期待効果
- 導入後の変化・メリット（定量・定性）

スライド5：スケジュール・費用感
- 想定スケジュール
- 費用感（記載できる範囲で）

スライド6：次のステップ
- 次のアクション（双方）
- 次回商談の目安
```

---

### 補足：ヒアリング不足の箇所

文字起こしから読み取れなかった情報・次回確認すべき点をリストアップする。

---

## 注意事項

- 出力は日本語
- 文字起こしにない情報は「不明（要確認）」と明記し、補完しない
- 顧客の課題は文字起こしの言葉ベースで整理する（解釈を加えすぎない）
- スライドはCanva手動作業の叩き台なので、骨子レベルで十分
- 提案内容はAIworkerの3サービス（研修・コンサル・開発）の範囲内で考える
